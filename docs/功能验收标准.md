# 福礼社平台 · 功能与页面验收标准

> 依据商业电商平台通用标准制定，覆盖功能正确性、金额与状态口径、权限隔离、幂等与审计、可用性与性能。
> 每个页面/功能给出可执行的验收点（AC），测试可直接转为用例。金额一律精确到分。

## 0. 全局验收基线（所有页面适用）

| 编号 | 验收标准 |
| --- | --- |
| G-01 | 未登录访问受保护接口返回 401，无权限返回 403，前端给出明确提示且不白屏。 |
| G-02 | 列表接口兼容 `current/size` 与 `pageNum/pageSize`，返回 `records/total`；翻页、筛选、重置行为正确。 |
| G-03 | 金额展示统一保留两位小数；后端资金以“分”存储，前端展示为“元”。 |
| G-04 | 状态流转不可跳步、不可逆（除审核驳回/退款等显式规则），重复操作有幂等保护或明确提示。 |
| G-05 | 商户/供应商/分销商数据严格按 `merchantId/supplierId/distributorId` 隔离，越权返回 403。 |
| G-06 | 所有写操作校验必填项、数值范围与枚举值；非法输入返回 400 且不产生脏数据。 |
| G-07 | 空列表显示空态，加载显示 loading，失败显示错误信息，不出现 undefined/NaN。 |
| G-08 | 关键操作（审核、退款、开票、红冲、结算、删除）二次确认并记录操作人与时间。 |
| G-09 | Mock 接口本地响应 P95 < 300ms；页面首屏可交互 < 2s（本地环境）。 |
| G-10 | 回归脚本 `verify-integrity / verify-authz / verify-supply-distribution` 全过，管理端与 H5 构建通过。 |

## 1. 管理后台

### 1.1 登录与鉴权
| 验收点 | 标准 |
| --- | --- |
| 账号密码登录 | 正确账号密码（默认 `123456`）登录成功并跳转工作台；错误提示不泄露账号是否存在。 |
| Token 失效 | 过期/非法 Token 自动跳转登录页，清除本地会话。 |
| 菜单权限 | 仅展示角色授权菜单；直接访问无权限路由被拦截。 |
| 数据范围 | 不同角色登录后可见数据范围与 `dataScope` 一致。 |

### 1.2 数据看板 / 商户工作台
| 验收点 | 标准 |
| --- | --- |
| 统计口径 | 销售额=已支付订单实付合计；待发货=订单状态 1；待退款=退款状态 <2；待结算=结算单状态 ≠2。 |
| 趋势图 | 近 6 个月采购/结算趋势与列表数据一致。 |
| 最新订单 | 按创建时间倒序，最多 6 条，金额与状态正确。 |
| 商户隔离 | 商户账号仅统计本商户数据；平台账号可切换商户。 |

### 1.3 商户资料
| 验收点 | 标准 |
| --- | --- |
| 查看/编辑 | 可查看并保存联系人、电话、邮箱、地址；必填校验生效。 |
| 越权 | 商户管理员不可编辑其他商户资料（403）。 |

### 1.4 商品管理（SPU / 分类 / 品牌）
| 验收点 | 标准 |
| --- | --- |
| 新增 | 名称必填；新增后生成默认 SKU；默认下架或按提交状态；新商品出现在 H5 首页「新品上架」。 |
| 编辑 | 修改价格/库存/名称后列表与 H5 详情同步；首页缓存已失效。 |
| 上下架 | 上架后 H5 可检索/推荐；下架后 H5 列表与详情不可见（已购订单仍可查看）。 |
| 删除 | 无关联订单可删除；批量删除含越权项时整批拒绝。 |
| 分类/品牌 | 关联后展示名称；删除被引用分类需拦截。 |
| 导入导出 | 模板字段完整，错误行有明确提示（如已实现）。 |

### 1.5 卡券管理（模板 / 卡券 / 批次）
| 验收点 | 标准 |
| --- | --- |
| 模板 CRUD | 面值/折扣、门槛、有效期、发放上限校验；折扣券 `discount∈(0,1)`，满减券面值>0。 |
| 批次发放 | 发放数量不超过模板剩余量；批次统计=发放/领取/核销。 |
| 卡券列表 | 状态（未使用/已使用/已过期）筛选正确；核销后不可重复核销。 |
| 权限 | 越权操作他商户卡券返回 403。 |

### 1.6 订单管理
| 验收点 | 标准 |
| --- | --- |
| 列表 | 支持订单号、用户、订单状态、支付状态筛选；多商户订单仅平台管理员可见。 |
| 详情 | 商品明细、金额（商品/运费/优惠/实付）、收货信息、支付/退款/发票状态一致。 |
| 发货 | 仅已支付待发货可发货；填写物流公司与单号；发货后状态 2。 |
| 取消/关闭 | 未支付可取消并释放锁定库存；已支付需走退款。 |
| 导出 | 导出字段与筛选结果一致。 |

### 1.7 支付与退款
| 验收点 | 标准 |
| --- | --- |
| 支付记录 | 支付单号、渠道、金额、状态与订单一致；重复回调不重复入账。 |
| 退款申请 | H5 申请仅登记待审核，不直接退款。 |
| 退款审核 | 通过后：退款出账 + 库存回补 + 佣金冲正 + 分账冲正；驳回则订单状态回退且无资金变化。 |
| 部分退款 | 退款金额 ≤ 实付；库存回补数量与退款明细一致。 |
| 幂等 | 重复审核同一退款单只产生一次资金变化。 |

### 1.8 发票管理（本轮新增）
| 验收点 | 标准 |
| --- | --- |
| 列表 | 按订单号、状态筛选；商户隔离；分页正确。 |
| 开具 | 仅待开票可开具；生成唯一发票号与开票时间；状态 0→1。 |
| 红冲 | 仅已开票可红冲；必须填写原因；生成红冲单号；保留原票，状态 1→2。 |
| 金额勾稽 | 发票金额 ≤ 订单实付；税额=金额×6%/(1+6%)，与订单一致。 |
| 重复申请 | 同订单存在待开票/已开票时再次申请被拒。 |
| 汇总 | 待开票数、已开票金额、已红冲数与列表一致。 |

### 1.9 平台抽佣（本轮新增）
| 验收点 | 标准 |
| --- | --- |
| 配置 | 技术服务费率 0%–20%，T+N 0–90 天；仅超级管理员可保存。 |
| 分账生成 | 支付成功按费率生成分账单；`平台服务费 + 商户应结 = 实付金额`（误差 < 0.01）。 |
| 分账明细 | 展示商户、实付、平台服务费、商户应结、供应商成本、分销佣金、状态。 |
| 退款冲正 | 退款审核通过后分账状态置为已退款，并生成平台服务费/商户应结冲正流水。 |
| 幂等 | 同一订单重复支付回调不重复生成分账单。 |
| 汇总 | 分账笔数、平台服务费、商户应结、已退款数与明细一致。 |

### 1.10 供应链（供应商 / 采购 / 库存 / 物流 / 结算）
| 验收点 | 标准 |
| --- | --- |
| 供应商 CRUD | 编号唯一；有采购单的供应商不可删除；商户隔离。 |
| 采购创建 | 商品须属于同一商户；供应商须属于该商户；数量>0，金额=单价×数量。 |
| 采购流转 | 仅 0→1→2→3；审核仅商户管理员，接单仅对应供应商，入库仅商户侧；重复入库拦截。 |
| 发货（本轮新增） | 仅状态 2 可发货；物流公司/单号必填；回传后页面展示单号。 |
| 签收（本轮新增） | 仅已发货且未签收可签收；记录签收人/时间；状态仍为 2，随后可入库为 3。 |
| 库存 | 入库仅更新一次库存；预警状态按可售库存计算。 |
| 结算单 | 应付=采购金额；已付+未付=应付；结算后状态 2 并记录结算时间。 |

### 1.11 营销（满减促销）
| 验收点 | 标准 |
| --- | --- |
| 配置 CRUD | 名称、门槛、减免、有效期、启停校验；减免 < 门槛。 |
| 生效范围 | 仅启用且在有效期内的规则参与 H5 计价。 |
| 多档取优 | 同时满足多档时取减免最大的一档，且不重复叠加。 |
| 金额一致性 | 下单页、订单详情、支付金额三处满减金额一致。 |

### 1.12 分销管理
| 验收点 | 标准 |
| --- | --- |
| 佣金规则 | 一级/二级佣金率 0–100%；绑定 SPU；启停与有效期生效。 |
| 分销商 | 审核/冻结状态流转正确；分销商仅见本人数据。 |
| 推广订单 | 展示归因人、层级、佣金、状态；退款后佣金失效。 |
| T+N | 完成后 N 天内为 PENDING/冻结，到期转可结算；未到期结算被拒。 |
| 二级上限 | 最多两级，超出不生成三级佣金。 |
| 自购 | 分销商自购不产生佣金。 |

### 1.13 分销商工作台（选品 / 分享 / 佣金）
| 验收点 | 标准 |
| --- | --- |
| 选品 | 仅展示上架且允许分销的商品；佣金率与规则一致。 |
| 分享链接 | 域名来自 `VITE_H5_BASE_URL`，带分销商与商品参数；可复制。 |
| 佣金明细 | 待结算/可结算/已结算/失效分类正确，金额合计一致。 |
| 结算 | 仅可结算状态可发起；结算后生成资金流水并置为已结算。 |

### 1.14 区块链与溯源
| 验收点 | 标准 |
| --- | --- |
| 交易/区块 | 高度递增、哈希关联、分页正确；数据不可编辑。 |
| 溯源查询 | 按溯源码返回原料—生产—检测—仓储—物流—签收链路；不存在的码给出明确提示。 |

### 1.15 系统管理（用户 / 角色 / 部门 / 菜单 / 租户）
| 验收点 | 标准 |
| --- | --- |
| 用户 | 新增/编辑/启停/重置密码；用户名唯一；手机号格式校验。 |
| 角色 | 菜单授权保存后重新登录生效；内置角色不可删除。 |
| 菜单 | 树形结构正确；新增菜单同步权限码与角色菜单。 |
| 租户 | 租户隔离；停用租户下账号不可登录。 |

## 4. 验收执行建议

1. 功能验收：按本表逐条执行，记录 AC 编号、结果、截图/接口返回。
2. 回归验收：每次改动后执行 `verify-integrity`、`verify-authz`、`verify-supply-distribution` 与双端构建。
3. 商业标准补充：金额一致性、状态不可跳步、越权隔离、幂等、审计留痕为“一票否决”项。
4. 交付边界：真实支付渠道、真实税务开票/税控对接不在 Mock 验收范围，需在接入真实服务后补充专项验收。
