> 测试目标：针对 **网页（管理端 + H5 商城）、小程序、公众号、App** 等不同形态，核对同一业务在各端的功能口径、接口契约、状态文案、金额与鉴权是否一致，并修复当前环境可闭环的不一致项。
>
> 证据原则：本报告所有结论均附**文件路径 + 行号**可追溯；动态结论以脚本实际运行输出为准，未在当前环境执行的项如实标注为「未验证」，不虚构「已通过」。

## 二、测试方法

1. **静态一致性核对**：逐端对比同一业务的 API 路径 / 请求方法 / 参数字段 / 响应字段 / 状态文案 / 金额口径 / 鉴权方式。以 Mock 的权威契约为基准（Mock 是三端唯一共享后端）。
2. **动态冒烟回归**：复用仓库既有脚本，自启独立端口 Mock，取得活的运行证据：
   - [verify-channel.cjs](file:///f:/百度同步/立项文件/0.南樾星数字科技/6.电商平台/福礼社平台/frontend/admin/mock/verify-channel.cjs)：Web / 小程序 / 公众号 三渠道协议层联调。
   - [verify-api-smoke.cjs](file:///f:/百度同步/立项文件/0.南樾星数字科技/6.电商平台/福礼社平台/frontend/admin/mock/verify-api-smoke.cjs)：79 请求全量接口冒烟 + 契约校验。
3. **编译/诊断回归**：管理端 `vue-tsc + vite build`；小程序编辑器诊断（`node_modules` 未安装，无法跑 weapp 编译，见交付边界）。
