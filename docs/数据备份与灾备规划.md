# 福礼社平台 数据备份与灾备规划

> 目标：防止服务器故障、磁盘损坏、误删、勒索软件等意外导致业务数据无法复原。
> 适用范围：Mock 演示环境（当前）与生产环境（规划）。

---

## 一、现状与风险

| 项 | 现状 | 风险等级 |
| --- | --- | --- |
| 数据存储 | Mock 进程**内存**中的 49 个数据集合 + `mock/seed*.cjs` 种子 | 高（进程退出即丢，靠种子重建） |
| 已有备份 | `mock/backup.cjs` 写后 800ms 防抖快照 + 5 分钟定时 + 手动，存 `frontend/admin/data/backups/{auto,manual}` | 中 |
| 备份介质 | **与源数据同一台机器、同一块磁盘**的本地 JSON | **致命** |
| 静态资源 | 商品图/视频为远程 URL，无本地 uploads | 低（但生产需纳入） |
| 数据库 | 无真实数据库 | — |
| 异地/离线副本 | 无 | **致命** |

**核心结论**：现有 `backup.cjs` 只能防"误操作/逻辑损坏"，防不住"服务器整机故障、磁盘损坏、机房事故、勒索加密"——因为备份和源数据同生共死。必须补齐**异地、异介质、不可变**副本。

---

## 二、备份目标（RPO / RTO）

| 环境 | RPO（最多丢多少数据） | RTO（多久恢复） | 副本要求 |
| --- | --- | --- | --- |
| 演示/POC | ≤ 5 分钟 | ≤ 10 分钟 | 本机 + 每日异地 |
| 生产（推荐） | ≤ 1 分钟（binlog 实时） | ≤ 30 分钟 | 3-2-1-1-0 |

**3-2-1-1-0 原则**：
- **3** 份副本（1 生产 + 2 备份）
- **2** 种介质（本地磁盘 + 对象存储/磁带）
- **1** 份异地（跨可用区或跨地域）
- **1** 份不可变（WORM/对象锁，防勒索与误删）
- **0** 错误（每份备份做校验和 + 定期恢复演练）

---

## 三、分层备份架构

```
                      ┌─────────────────────────────┐
   写入 ─────────────▶│ 生产数据（内存/MySQL）        │
                      └──────────────┬──────────────┘
                                     │
        ┌────────────────────────────┼────────────────────────────┐
        ▼                            ▼                            ▼
  L0 应用快照                  L1 本地归档                  L4 代码与配置
  backup.cjs                 每日全量打包                   Git + 发布产物
  写后防抖 + 5min             gzip + sha256                 + .env/证书加密
  同级 data/backups           同级 archives/                （离线保管）
        │                            │
        └────────────┬───────────────┘
                     ▼
              L2 异地对象存储（跨可用区，推荐开启对象锁/WORM）
              每日全量 + 增量，保留 90 天
                     │
                     ▼
              L3 跨地域冷备（每周，另一地域/离线介质，保留 1 年）
```

| 层 | 内容 | 频率 | 保留 | 介质/位置 | 加密 | 校验 |
| --- | --- | --- | --- | --- | --- | --- |
| L0 应用快照 | 49 个集合 JSON（已有） | 写后 800ms / 5min | 自动 40 份、手动 100 份 | 本机磁盘 | 否（现状） | 结构校验 |
| L1 本地归档 | L0 全量打包 | 每日 02:00 | 30 天 | 本机另一分区 | AES-256 | sha256 |
| L2 异地对象存储 | 每日全量 + 增量 | 每日 / 每小时增量 | 90 天 | 对象存储（跨可用区，WORM） | SSE + 客户端加密 | sha256 + 大小比对 |
| L3 跨地域冷备 | 每周全量归档 | 每周日 | 1 年 | 另一地域 / 离线介质 | 是 | 恢复抽检 |
| L4 代码与配置 | 源码、构建产物、`.env`、证书、Nginx | 每次发布 | 永久（Git 历史） | Git 远端 + 加密保管 | 密钥单独保管 | 可构建验证 |

## 四、备份对象清单（生产口径）

| 分类 | 具体对象 | 优先级 | 说明 |
| --- | --- | --- | --- |
| A 核心业务数据 | 订单、支付流水、退款、资金流水、库存、佣金、分账、发票 | **P0** | 丢失不可逆，必须异地+不可变 |
| B 商品与内容 | 商品/SPU/SKU、分类、评价、溯源记录 | P1 | |
| C 配置与元数据 | 租户、用户、角色、菜单、权限、促销/满减规则 | P1 | 决定系统能否正确启动 |
| D 静态资源 | 商品图/视频、发票 PDF、对账单导出 | P2 | 对象存储开版本化 |
| E 代码与部署 | 源码、镜像、Nginx、`.env` | P1 | Git + 制品库 |
| F 密钥与证书 | JWT 密钥、支付/开票密钥、TLS 证书 | **P0** | 加密离线保管，不进 Git |

> 当前 Mock：A–C 即 `backup.cjs` 的 49 个集合 + `seed*.cjs`；D 为远程 URL（上线后迁到自有对象存储）；E 为仓库代码；F 为 `.env`。

## 五、恢复流程与演练

| 故障场景 | 恢复来源 | 步骤 | 目标 RTO |
| --- | --- | --- | --- |
| 误删某条/某批数据 | L0 快照 | 管理端「数据备份」页选快照→恢复→校验 | ≤ 5 分钟 |
| 数据逻辑损坏 | L1 当日归档 | 解压→解密→`backup.restore`→校验 | ≤ 15 分钟 |
| 磁盘损坏 | L2 对象存储 | 新盘挂载→拉取最近全量+增量→恢复 | ≤ 30 分钟 |
| 整机/机房故障 | L2/L3 异地 | 新机器：Git 拉代码→装依赖→恢复数据→恢复配置/证书→启动 | ≤ 1 小时 |
| 勒索加密 | L2 WORM / L3 离线 | 从未被篡改的不可变副本恢复 | ≤ 1 小时 |
| 数据被恶意篡改 | L1/L2 历史版本 | 选篡改前时点快照恢复 | ≤ 30 分钟 |

**演练制度**（关键，备份不等于可恢复）：
- **每月**：自动恢复演练——在隔离沙箱还原最近 L1/L2 快照，跑一致性校验（复用 `verify-user-consistency.cjs` 与 `simulate-lifecycle.cjs`），记录结果与耗时。
- **每季度**：真实切换演练——模拟整机故障，从异地副本在备用环境全量重建并对外验证。
- 演练报告归档至 `docs/备份演练记录.md`，保留最近 4 次。

## 六、监控与告警

| 指标 | 阈值 | 动作 |
| --- | --- | --- |
| 备份任务成功/失败 | 任一失败 | 企业微信/邮件告警，5 分钟未恢复升级 |
| 备份文件校验和不匹配 | > 0 | 立即告警并重传 |
| 异地同步延迟 | > 1 小时 | 告警 |
| 备份容量水位 | > 80% | 告警 |
| 最近成功备份时间 | 超过 2× 周期 | 告警（防止"静默失败"） |
| 恢复演练失败 | 任一失败 | 阻断发布并排查 |

## 七、与现有 `backup.cjs` 的衔接

- **保留 L0 不变**：`mock/backup.cjs` 作为应用层实时快照，继续服务管理端「数据备份」页，覆盖误删/逻辑损坏。
- **新增 `mock/backup-offsite.cjs`**（规划）：定时读取 `data/backups` 最新快照 → 打包 gzip → 计算 sha256 → 上传对象存储（L2）→ 按 90 天轮转 → 失败告警。
- **新增 `mock/backup-verify.cjs`**（规划）：拉取最新备份 → 解密解压 → 还原到临时目录 → 校验集合数与关键断言 → 输出演练报告。
- **生产切库后**：L0 快照由"内存序列化"改为"MySQL 全量 dump + binlog 增量"，RPO 从 5 分钟降到 ≤ 1 分钟。

## 八、实施路线

| 阶段 | 内容 | 交付 | 优先级 |
| --- | --- | --- | --- |
| **P0** | 每日全量打包 + sha256 + 上传异地（对象存储/异地目录）+ 失败告警 | `backup-offsite.cjs` + 计划任务 | 立即 |
| **P1** | 本地归档保留 30 天、对象存储开启版本化/对象锁、恢复演练脚本 | `backup-verify.cjs` + 演练报告 | 1 周 |
| **P2** | 接 MySQL binlog 实时增量、跨可用区、跨地域冷备、监控看板 | 生产灾备体系 | 1 月 |
| **P3** | 季度真实切换演练、合规留存（资金/发票按年限） | 演练与合规台账 | 持续 |

**成本参考**：当前全量快照约 337 KB/份，日全量 + 90 天保留 ≈ 30 MB，对象存储成本可忽略；生产按数据量线性增长。

## 九、待确认的决策点

1. **部署形态与云厂商**：阿里云 / 腾讯云 / 自建机房？（决定用 OSS / COS / 自建 MinIO）
2. **RPO/RTO 目标**：生产是否要求 RPO ≤ 1 分钟（需 binlog）？
3. **是否已有异地资源**：现有可用的对象存储桶或异地服务器？
4. **合规留存**：资金/发票/佣金数据是否有法定保留年限要求？
5. **密钥保管方式**：JWT/支付/开票密钥采用何种离线加密保管（KMS / 密码管理器 / 保险柜）？

## 十、说明

本文件为**规划方案**。当前已落地的仅为 L0（`backup.cjs`，已验证可备份/恢复/回滚 49 个集合）。L1–L4 需在明确上述决策点后实施；在完成异地副本前，**当前环境仍无法抵御服务器整机或磁盘级故障**。
