# 数据库设计说明

## 一、设计原则

### 1.1 命名规范

- **表名前缀**：按业务域划分，便于管理
  - `sys_` - 系统管理（用户、租户、权限）
  - `pms_` - 商品管理（Product Management System）
  - `cms_` - 卡券管理（Coupon Management System）
  - `oms_` - 订单管理（Order Management System）
  - `acc_` - 账户管理（Account）
  - `pay_` - 支付管理（Payment）
  - `bas_` - 基础数据（Base）

- **字段命名**：下划线分隔，全小写
- **主键**：统一使用 `id`，bigint 自增
- **时间字段**：`create_time`、`update_time`
- **逻辑删除**：`deleted` 字段，0-未删除，1-已删除
- **租户字段**：`tenant_id`，多租户隔离

### 1.2 通用字段

每张业务表都包含以下通用字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | bigint | 主键，自增 |
| tenant_id | bigint | 租户ID（多租户隔离） |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |
| deleted | tinyint | 逻辑删除标志 |

## 二、业务域详细设计

### 2.1 用户租户域 (sys_*)

#### 核心表

| 表名 | 说明 | 核心字段 |
| :--- | :--- | :--- |
| sys_tenant | 租户表 | tenant_name, tenant_code, tenant_type, status |
| sys_user | 用户表 | username, password, mobile, user_type, dept_id |
| sys_dept | 部门表 | parent_id, dept_name, ancestors |
| sys_role | 角色表 | role_name, role_key, data_scope |
| sys_user_role | 用户角色关联 | user_id, role_id |
| sys_menu | 菜单表 | parent_id, menu_name, path, perms |
| sys_role_menu | 角色菜单关联 | role_id, menu_id |

#### 设计要点

1. **多租户设计**：所有业务表都有 `tenant_id` 字段，通过 MyBatis-Plus 多租户插件自动过滤
2. **用户类型**：
   - 1 - 普通员工
   - 2 - 企业管理员
   - 3 - 超级管理员（平台运营）
3. **数据权限**：通过角色的 `data_scope` 字段控制数据范围
4. **部门树**：使用 `parent_id` + `ancestors` 实现部门层级结构

### 2.2 商品域 (pms_*)

#### 核心表

| 表名 | 说明 | 核心字段 |
| :--- | :--- | :--- |
| pms_category | 商品分类 | parent_id, name, level |
| pms_brand | 品牌表 | name, logo |
| pms_spu | 商品SPU | spu_no, name, category_id, brand_id, status |
| pms_sku | 商品SKU | sku_no, spu_id, price, stock |
| pms_spec | 规格表 | name |
| pms_spec_value | 规格值表 | spec_id, value |

#### 设计要点

1. **SPU/SKU 模型**：
   - SPU（Standard Product Unit）：标准产品单元，如"iPhone 15"
   - SKU（Stock Keeping Unit）：库存量单位，如"iPhone 15 黑色 128G"
   
2. **库存设计**：
   - `stock` - 可用库存
   - `locked_stock` - 锁定库存（下单时锁定，支付成功扣减）
   
3. **规格设计**：规格与规格值分离，支持多规格组合

### 2.3 卡券域 (cms_*)

#### 核心表

| 表名 | 说明 | 核心字段 |
| :--- | :--- | :--- |
| cms_coupon_template | 卡券模板 | template_name, coupon_type, face_value, validity |
| cms_coupon | 卡券实例 | coupon_code, template_id, balance, status, user_id |
| cms_coupon_batch | 发放批次 | batch_name, template_id, total_count, status |
| cms_coupon_use_record | 使用记录 | coupon_id, order_id, used_amount |

#### 设计要点

1. **模板 + 实例分离**：
   - 模板定义卡券的规则（面值、有效期、适用范围）
   - 实例是具体的一张卡（卡号、密码、状态、持有人）
   
2. **卡券状态流转**：
   ```
   未领取 → 已领取未使用 → 已使用
              ↓
            已过期 / 已作废
   ```

3. **卡券类型**：
   - 1 - 定额卡（固定金额，可分次使用）
   - 2 - 权益卡（指定商品/服务）
   - 3 - 组合卡（多张卡的集合）

4. **余额设计**：定额卡有 `balance` 字段，支持分次使用

### 2.4 订单域 (oms_*)

#### 核心表

| 表名 | 说明 | 核心字段 |
| :--- | :--- | :--- |
| oms_cart | 购物车 | user_id, sku_id, quantity |
| oms_order | 订单表 | order_no, user_id, total_amount, status |
| oms_order_item | 订单商品 | order_id, sku_id, price, quantity |
| oms_user_address | 收货地址 | user_id, receiver_name, receiver_phone |

#### 设计要点

1. **订单状态流转**：
   ```
   待支付 → 待发货 → 已发货 → 已完成
     ↓        ↓
   已取消   售后中
   ```

2. **订单金额字段**：
   - `total_amount` - 订单总金额（商品总金额）
   - `discount_amount` - 优惠金额
   - `coupon_amount` - 卡券抵扣金额
   - `freight_amount` - 运费
   - `pay_amount` - 实付金额 = 总金额 - 优惠 - 卡券 + 运费

3. **订单商品快照**：订单商品表冗余商品名称、图片、价格等信息，防止商品变更影响历史订单

4. **购物车**：按用户 + SKU 唯一，支持选中状态

### 2.5 支付账户域 (acc_*, pay_*)

#### 核心表

| 表名 | 说明 | 核心字段 |
| :--- | :--- | :--- |
| acc_account | 账户表 | user_id, account_type, balance, frozen_amount |
| acc_account_flow | 账户流水 | account_id, flow_type, amount, balance_before/after |
| pay_order | 支付订单 | order_id, pay_channel, pay_amount, pay_status |
| pay_refund | 退款订单 | pay_order_id, refund_amount, refund_status |

#### 设计要点

1. **统一账户模型**：
   - 五种账户类型共用一张表，通过 `account_type` 区分
   - 账户类型：1-福利卡额度 2-餐补 3-劳保 4-积分 5-健康
   
2. **资金安全**：
   - `balance` - 可用余额
   - `frozen_amount` - 冻结金额
   - 所有变动都记录流水，支持对账和审计
   
3. **账户流水**：
   - 每笔变动都有唯一流水号
   - 记录变动前后余额
   - 记录业务关联（业务类型、业务ID、业务单号）
   
4. **支付订单**：
   - 与业务订单解耦，支持多渠道支付
   - 支持同一订单多次支付（失败重试）
   - `pay_status` 状态机管理支付状态

## 三、索引设计原则

### 3.1 必建索引

1. **主键索引**：每张表的 `id` 字段
2. **唯一索引**：业务唯一字段（如 order_no, coupon_code 等）
3. **租户索引**：所有业务表的 `tenant_id` 字段
4. **时间索引**：`create_time` 字段（查询列表时常用）

### 3.2 常用查询索引

根据业务查询场景添加：
- 用户表：`mobile`、`username`
- 订单表：`user_id`、`status`
- 卡券表：`template_id`、`user_id`、`status`
- 账户流水：`account_id`、`user_id`

### 3.3 索引命名规范

- 普通索引：`idx_字段名`
- 唯一索引：`uk_字段名`
- 联合索引：`idx_字段1_字段2`

## 四、后续演进

### 4.1 分库分表

当单表数据量超过 500 万时，考虑使用 ShardingSphere 进行分库分表：

- **订单表**：按 `user_id` 或 `create_time` 分表
- **账户流水表**：按 `account_id` 或 `create_time` 分表
- **操作日志表**：按 `create_time` 分表

### 4.2 数据归档

冷数据定期归档：
- 历史订单：归档到历史库
- 操作日志：归档到 ClickHouse 或 ES

### 4.3 读写分离

主库负责写，从库负责读：
- 主库：增删改操作
- 从库：查询操作（通过 MyBatis-Plus 动态数据源切换）
