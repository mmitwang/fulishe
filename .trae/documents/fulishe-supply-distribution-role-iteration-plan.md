# 福礼社多租户供应链与推广分销迭代计划

## Context

系统已有平台、商户、采购、运营、消费者基础能力，也已有供应商、采购、库存、物流、结算页面；但供应链 Mock 接口尚未统一认证和数据隔离，供应商没有独立身份，分销业务尚未实现。本轮以“推广佣金分销”为分销定义，目标不是堆叠静态菜单，而是让平台、商户、供应商、分销商、消费者完成可浏览器操作的真实业务闭环，同时保持现有订单状态机、满减和福卡账本不变。

## 一、角色与功能边界

| 用户 | 数据范围 | 本轮可用功能 | 明确禁止 |
|---|---|---|---|
| 平台管理员 | ALL | 全局监督、供应商/分销商管理、分销规则、推广订单、佣金结算确认 | 不代替商户伪造业务归属 |
| 商户管理员 | MERCHANT | 本商户采购、库存、供应链、商品佣金规则、推广订单 | 跨商户读写、平台佣金结算 |
| 采购专员 | MERCHANT | 本商户供应商、采购、收货、库存 | 分销配置、结算确认 |
| 运营专员 | MERCHANT | 本商户商品、订单、分销规则与推广效果 | 采购成本、库存调整、结算确认 |
| 供应商 | SUPPLIER | 本人资料、关联采购单、确认接单、对账明细 | 新建/审核采购单、改库存、确认结算、查看其他供应商 |
| 分销商 | DISTRIBUTOR | 本人选品、生成分享、推广订单、佣金明细 | 查看消费者隐私、他人业绩、修改佣金率 |
| 消费者 | SELF | 打开分享、购物车/下单/支付、本人订单与福卡 | 管理端及他人数据 |

新增 `supplier`、`distributor` 角色和独立演示账号。用户记录增加可空 `supplierId/distributorId`，身份每次由服务端用户记录构建，JWT 仍只标识用户，绝不信任请求中的归属 ID。权限取角色并集，各资源按对应归属单独收敛，避免混合角色扩大数据范围。

## 三、迭代 2：推广选品到佣金闭环

### 最小领域模型

- `distributors`：分销商身份、关联用户、状态。
- `distributionRules`：商户、SPU、佣金率、有效期、启停状态。
- `distributionSelections`：分销商选品关系与状态。
- `distributionShares`：分享 ID、分销商、商户、SPU、规则快照、失效时间。
- `promotionOrders`：订单项、订单号、商户、分销商、佣金基数、费率、佣金、状态；以订单项 + 分销商保证幂等。

佣金只使用整数分计算；满减/优惠按订单项金额比例分摊，所有份额之和必须等于订单实付分摊额。状态采用 `PENDING → SETTLEABLE → SETTLED`，退款转为 `INVALID`。本期只做一级推广和 Mock 结算，不做多层级、团队、提现或真实资金划转。

### 接口与页面

1. 新增 `routes-distribution.cjs` 和独立服务：商户管理规则与查看本商户推广单；分销商选品、创建分享、查看本人推广单；平台确认可结算佣金；所有列表和写操作做行级隔离。
2. 新增管理端“分销管理”和“分销商工作台”两组路由/页面。分销管理包含规则、分销商、推广订单；工作台包含选品中心、分享链接、推广订单和佣金统计，提供加载、空态、失败和重复点击反馈。
3. 分享使用服务端持久化的不透明 `shareId`，同时输出浏览器 H5 地址 `/product/:id?shareId=...` 和 Taro 路径 `/pages/product/index?id=...&shareId=...`，不引入新依赖。
4. 在 Vue H5 的 `product/detail.vue`、`order/confirm.vue` 与 Taro 的 `src/pages/product/index.tsx`、`src/services/trade.ts` 复用同一归因 API：按 SPU 保存最后有效点击，下单时逐项携带 shareId；校验商品匹配、有效期、撤品和分销商自购。
5. 下单只保存归因/费率快照，支付成功才生成佣金。普通支付、福卡支付、支付回调、订单完成和退款统一调用幂等的分销旁路服务；不得修改现有支付金额、状态迁移和福卡流水规则。

## 四、内置浏览器逐步验收与优化

启动 Mock（8080）、管理端（3100）和 Vue H5（3001），每个角色使用独立会话或退出后重登，保存关键步骤截图、控制台错误和失败请求。

1. 平台管理员查看全局数据，创建/启停分销规则，验证直接 URL 与接口权限一致。
2. 商户 A 新建采购单并审核、配置商品 10% 佣金；商户 B 不可见且伪造 ID 操作失败。
3. 供应商只看到自己的采购单并接单，无库存和结算操作；商户确认入库，核对库存只增加一次。
4. 分销商选品并复制真实分享链接，只能看到本人数据。
5. 消费者在新的浏览器会话打开 H5 分享链接，选择规格、填写地址、提交订单并完成模拟支付，页面显示支付成功。
6. 分销商核对推广订单和优惠后佣金；重复支付/回调仍只有一笔。订单完成后佣金可结算，平台确认后已结算；另建订单验证退款使佣金失效。
7. 每轮发现越权、状态绕过、金额误差、重复提交、布局溢出或反馈不清就最小修复，再重跑当前场景和全量回归。
