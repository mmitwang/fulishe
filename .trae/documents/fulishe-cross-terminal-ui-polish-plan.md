# 福礼社跨终端界面优化计划

## Context

福礼社已经具备完整的首页、分类、商品、购物车、结算、订单、个人中心和福卡链路，也已有朱红、暖金、米白的品牌基础。但当前多数页面仍以同一套移动卡片布局直接扩展到桌面端：首页主视觉与内容容器关系不清，商品详情仅限制页面宽度，固定操作栏在宽屏下分散，部分触控区、选中态、空态和焦点反馈不统一。

本轮使用 UICraft，在保留全部业务逻辑的前提下，形成“东方礼赠、现代商城”的统一体验，让桌面网站、公众号 H5 和微信小程序都具有清晰层级、舒适阅读和可靠交互。

## 范围与约束

- 优先改造消费者端 Taro/React 工程，覆盖主导航、核心交易页面和福卡页面；登录、溯源、渠道等辅助页面继承同一套基础规范。
- 管理端 Vue/Element Plus 本轮不改，避免把运营后台与消费者商城混为同一种视觉和交互。
- 不修改 `src/services`、store、Mock 数据、路由参数、订单状态或福卡资金逻辑；不接真实微信/支付，不新增依赖或外部图片。
- 保留现有商品图、懒加载、Taro 条件编译、原生 tabBar 和 `designWidth/pxtransform` 配置。

## 实施步骤

### 1. 统一设计基础

修改 `src/styles/theme.scss`、`variables.scss`、`compat.scss`、`app.scss`：

- 延续“朱砂红、宣纸米白、墨色正文、暖金点缀”，补齐选中背景、焦点、骨架屏、遮罩等语义 token，减少页面散落色值。
- 统一内容最大宽度、页面间距、卡片圆角、细边框和轻阴影；宋体仅用于品牌标题与礼赠重点，正文继续使用系统中文字体。
- 建立可复用的内容容器、主要按钮、焦点和减少动态效果 mixin；保留 rpx 体系。
- 主要触控区统一至约 88rpx，补充触屏 `:active`、H5 精确指针 hover、键盘 focus-visible 与 `prefers-reduced-motion`，不引入动画库。

### 2. 统一商品表达与主导航页面

修改 `src/components/ProductCard/*`、`home`、`category`、`cart`、`mine` 的页面样式，必要时做少量 TSX 容器调整：

- 商品卡固定图片比例、两行标题、品牌/销量和价格基线，压缩浮卡感；保留点击回调、图片懒加载和原有点击区域。
- 首页按“品牌主张 → 搜索 → 礼赠场景 → 分类 → 服务保障 → 今日甄选”组织。为 hero 增加内部限宽容器，使桌面背景全宽、内容居中；搜索不再依靠不协调的负边距浮叠。
- 手机保持双列商品，平板三列，桌面四列；宽屏内容限制在约 1200px 内，不无限拉伸。
- 分类页统一选中态与横向/纵向滚动反馈；购物车强化勾选、商品、数量、价格扫描线，底部结算栏增加限宽内层。
- 我的页面统一用户资料、福卡入口、订单统计和功能列表的标题与按钮层级，减少重复渐变装饰。

### 3. 优化核心交易与福卡链路

修改 `product`、`checkout`、`order`、`card` 及必要的辅助页面样式：

- 商品详情在桌面采用“左图右摘要/规格”的双栏结构，参数与详情置于下方；手机保持现有浏览顺序。购买底栏限宽居中，视频切换、规格、数量与缺货状态保持原逻辑。
- 结算页统一收货表单、商品清单、支付方式和金额区域；支付选中态同时使用边框、文字和标记，不只依靠颜色。保留福卡余额、全额支付及 Mock 说明。
- 订单页保留 sticky 横滑 tab、高亮订单和全部操作，统一状态标签、实付金额、主次按钮；窄屏下操作按钮允许合理换行，避免挤压订单号与金额。
- 福卡保留高识别度深色余额卡，但收敛渐变，优化充值/送礼切换、金额预设、流水金额正负层级和错误重试。
- 登录、溯源、渠道、运营说明等辅助页面只继承排版、间距、按钮和空态规范，不重写业务结构。

### 4. 响应式与交互收尾

- 复用现有 `@media (min-width: 768px)` 模式，增加少量一致的中宽/宽屏断点；不使用 JS 监听窗口实现布局。
- 三处固定操作栏统一安全区和限宽内层，核对页面底部 padding；购物车继续使用现有 H5 `/* #ifdef h5 */` 避让，小程序保留原生 tabBar 行为。
- 主要操作补充必要的无障碍名称和焦点样式，但不批量更换 Taro 组件或改变事件顺序。
- 统一加载、空、错误状态为“明确说明＋下一步操作”；不新增网络请求、大面积滤镜、 backdrop-filter 或布局抖动。

## 关键文件

- 基础：`src/styles/{theme,variables,compat}.scss`、`src/app.scss`
- 共享：`src/components/ProductCard/index.tsx`、`index.module.scss`
- 主页面：`src/pages/{home,category,cart,mine}/index.tsx` 及对应 `index.module.scss`
- 交易与福卡：`src/pages/{product,checkout,order,card}/index.tsx` 及对应 `index.module.scss`
- 辅助页面仅在确有必要时调整对应 SCSS/语义，不修改服务与 Mock 文件

## 验证

1. 以当前云端预览记录首页、商品、购物车、结算、订单、我的和福卡基线；实施后逐页对比视觉层级、溢出、遮挡和交互反馈。
2. 在约 375px、768px、1440px 视口检查商品网格、双栏商品详情、固定底栏、横滑 tab、文本换行与触控面积；检查键盘焦点和减少动态效果。
3. 使用现有云端 H5 编译链路并尝试 `npm run build:h5`、`npm run build:weapp`；若本地迁移依赖仍限制构建，明确记录，不将转译检查冒充完整验收。
4. 走通首页 → 商品 → 规格/数量 → 购物车 → 结算 → 订单，分别验证模拟微信与福卡支付，确认路由和业务事件未受样式调整影响。
5. 使用 `zhangsan / 123456` 复核福卡充值、转赠、余额不足、退款及刷新一致性；执行 `node frontend/admin/mock/verify.cjs`，确认既有自动化测试保持通过。
6. 最终汇报区分浏览器实测、H5/小程序构建结果与仍需微信开发者工具或真机验证的项目。
